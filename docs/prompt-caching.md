Generation throughput
---------------------
Approved assets run through at most three concurrent worker pipelines. Each worker
owns its model client and independently writes, selects an image, validates, and
repairs its asset. The coordinator alone writes campaign generation state, saves
results as workers finish, and preserves plan order. Failed assets leave successful
results saved; an explicit retry skips completed assets. Model run logs retain
independent provider attempts. No automatic provider retries or prewarming are added.

Planning shares rule packs and evidence by reference. Generation keeps original
passages once and retains nonverbatim summaries and restrictions. Image selection
receives deduplicated channel, voice, visual, legal and campaign guidance; unrelated
product, case-study and research passages are excluded unless they mention visual
content. Stored evidence packages are unchanged.

An offline replay of the reviewed six-asset campaign reduced representative
serialized request character counts by approximately 69% for planning, 69% for
generation and 59% for image selection. These are payload-size measurements, not
measured token or latency reductions. Verify actual runtime on the next authorized
campaign generation; existing drafts are not regenerated by deploying this change.

Review-budget recovery
----------------------
Conflict discovery and independent checking preflight the full request, including
the preceding review and output schema. Oversized inputs use lossless overlapping
batches: each source-passage pair is included together and the complete brief is
repeated in every batch. Findings are merged with exact duplicates removed. Batch
results are checkpointed independently, so a retry reuses successful work.
Coverage remains incomplete until every required batch and both logical passes
succeed. Requests whose essential fixed context or an individual passage cannot
fit still report a substantive size error; no evidence is silently truncated.

Agent selection and preparation (requirements, retrieval, planning and read-only
answers) recover once from timeouts, invalid model output, transient connections,
429 responses and server errors. Recovery events and individual provider attempts
remain recorded. Previously committed preparation checkpoints are reused. Saved
copy/image edits, approval and generation are not automatically replayed. Missing
essential evidence, refusal, configuration and logging failures are not treated
as successful work, and persistent failures remain visible rather than looping.
